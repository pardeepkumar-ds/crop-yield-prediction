Crop Yield Prediction Using Machine Learning

Forecasting crop yields from climate and agricultural data to support smarter agricultural planning.

This notebook builds, evaluates, and compares several machine learning models that predict crop yield (tonnes/hectare) from historical climate conditions (rainfall, temperature), pesticide usage, crop type, and country. It follows the standard project structure: data understanding → preprocessing → exploratory data analysis → feature engineering → model training → evaluation → conclusions.

1. Introduction

Crop yield prediction is one of the most practically important problems in agricultural data science. Reliable forecasts help farmers plan sowing and irrigation schedules, help input suppliers plan fertilizer and pesticide distribution, help governments plan food security and storage policy, and help insurers and commodity traders price risk.

Yield is shaped by a complex mix of factors — weather (rainfall, temperature), soil and input management (pesticide/fertilizer use), the crop being grown, and the region's agricultural practices. Machine learning is well suited to this problem because it can learn non-linear relationships between these factors and yield directly from historical data, without requiring an explicit mechanistic (biophysical) crop model.

2. Objective

  • Predict crop yield (tonnes per hectare) from climate, pesticide-use, crop, and country data using ML models.
  • Identify which environmental and agricultural factors influence yield the most.
  • Compare multiple regression approaches (linear, regularised, polynomial, and a tree-based model) to understand the trade-off between interpretability and predictive accuracy.

3. Dataset

We use the Crop Yield Prediction data (Kaggle), which compiles four public sources — FAO crop yield statistics, World Bank rainfall data, FAO pesticide-use data, and historical average-temperature records — along with yield_df.csv, a pre-merged table that joins all four sources on country (Area) and year. The merged dataset covers 101 countries, 10 crops, and the years 1990–2013.

6. Feature Engineering

The original brief lists feature ideas (growing degree days, fertilizer-to-soil ratio, drought index) designed for a dataset with daily weather and separate soil/fertilizer records. Our actual data is annual-average climate + pesticide totals only — there is no daily temperature, soil type, or fertilizer-tonnage field available. Rather than fabricate columns the data can't support, we adapt the same ideas to what's genuinely available:

Brief's idea Adapted feature here Why
Growing degree days (omitted) Requires daily min/max temperature, which this dataset doesn't have
Fertilizer-to-soil ratio pesticide_intensity = pesticides ÷ rainfall Pesticide use is the only input-management variable available; rainfall is used as the denominator since soil data is absent
Drought index drought_index_proxy = temperature ÷ rainfall Higher temperature with lower rainfall approximates drought stress
— rainfall_temp_interaction = rainfall × temperature Captures the combined climate effect the EDA above suggests matters more than either variable alone
— years_since_start Captures technology/practice improvements over time (irrigation, better seed varieties, etc.)

7. Model Training

We train the models requested in the brief — Linear Regression, Ridge, Lasso, and Polynomial Regression (degree 2, applied to the numeric climate/pesticide features only, to avoid an explosion of interaction terms with the 100+ one-hot columns) — plus a Random Forest as a tree-based point of comparison (the brief notes "both regression and tree-based models work well" for this problem), which also gives us genuine feature importances for Section 9.

In [15]
results = []

def evaluate(name, y_true, y_pred):
    rmse = np.sqrt(mean_squared_error(y_true, y_pred))
    mae = mean_absolute_error(y_true, y_pred)
    r2 = r2_score(y_true, y_pred)
    results.append({'Model': name, 'RMSE': rmse, 'MAE': mae, 'R2': r2})
    print(f"{name:22s}  RMSE={rmse:8.3f}  MAE={mae:8.3f}  R2={r2:6.4f}")

11. Conclusions & Recommendations

Results. Across 25,932 country-crop-year records and 116 engineered/encoded features, the models achieved:

Model R2 RMSE (t/ha) MAE (t/ha)
Random Forest (bonus) 0.9780 1.263 0.570
Linear Regression 0.7488 4.267 2.991
Ridge Regression 0.7486 4.268 2.987
Polynomial Regression 0.7483 4.271 3.004
Lasso Regression 0.7273 4.446 2.972
  • Random Forest (bonus) was the best performer (R2 = 0.9780), substantially ahead of the best linear approach, Linear Regression (R2 = 0.7488). This gap confirms the EDA finding that yield depends on non-linear, interacting effects of crop, country and climate rather than a simple additive combination of them.
  • The single most informative feature was Item_Potatoes (importance approx 0.377), i.e. which crop is being grown dominates the prediction -- unsurprising, since different crops have very different yield scales (e.g. potatoes vs. sorghum), but it also means country and climate features matter most for refining the prediction within a given crop, not for separating crops from each other.
  • For agricultural planning, this suggests the tree-based model is the better operational choice (highest accuracy), while the linear models remain useful for communicating simple, interpretable relationships (coefficient signs/magnitudes) to non-technical stakeholders.
  • Recommendation: deploy the Random Forest for yield forecasting where accuracy is the priority, and pair it with the linear model's coefficients when the explanation of why a forecast changed is needed for policy or planning conversations.

12. Limitations & Future Work

  • No soil or fertilizer data. The dataset provides pesticide totals but not fertilizer tonnage or soil type/quality, so those effects can't be modelled directly here.
  • Annual, not daily, climate data. True growing-degree-days and within-season drought indices require daily temperature/precipitation; only yearly averages were available.
  • Country-level granularity. Yield is averaged at the country level, which hides regional and farm-level variation.
  • Next steps: source sub-national weather and soil data, try gradient-boosted trees (XGBoost/LightGBM) and hyperparameter tuning (grid/randomised search with cross-validation), and validate on more recent years (this dataset ends in 2013).
